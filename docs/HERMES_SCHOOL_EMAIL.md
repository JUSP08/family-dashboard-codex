# Hermes school-email ownership

The user approved OpenRouter interpretation of selected school, ParentSquare, and sportsYou email text and automatic family-calendar/reminder updates on 2026-11-10. Home layout, bus announcements, and 07:30 weekday briefing routing remain unchanged.

Hermes cron runs the installed `school-email-job.py` wrapper every 15 minutes, using the dashboard Python. Its scheduler uses script mode to avoid a second general-purpose agent invocation: the script itself invokes the real Hermes `AIAgent` with `openai/gpt-6-luna` via OpenRouter, an empty tool list, and no memory/context-file injection. This is actual Hermes inference, not a direct substitute API client. Gmail access is read-only, with sender/privacy filtering inherited from school_email_service. Raw mail never becomes a shell command. Each agent call is bounded to 20 messages/80k characters and a 240-second process timeout.

Only validated proposals with matching source IDs and verbatim evidence can pass. Calendar publishing is restricted to `customEvents` with revision checking. Matching manual entries are preserved. Hermes entries contain source links and a snapshot; user edits prevent subsequent automatic overwrites. Connected-calendar duplicates are skipped, conflicts retained for review. No Google Calendar writes occur. Optional activities are reminders. Future reschedules that cannot confidently match are a remaining interpretation limitation; review source emails.

Private state, extraction cache, last preview, errors, and per-write calendar backups live in `~/.config/family-dashboard-school-email/` (owner-only). Calendar state also receives a deployment backup. Source text is sent to the configured external provider under explicit consent; source excerpts and proposed reminders are persisted privately. Hermes's own inference logging/retention follows its installed runtime settings.

Set `SCHOOL_EMAIL_OWNER=hermes` in backend .env to stop the dashboard's previous scanner. The dashboard still consumes the refreshed feed and runs the briefing. On failure the feed reports an error and omits stale reminders. The `school-email` Hermes plugin provides status and scan-request tools. Manual runs are serialized with a lock. Recent-message fingerprints prevent repeated inference; fresh messages and future reminders are revisited on subsequent scheduled ticks.

Rollback: pause the Hermes cron job first; restore backend .env and source from the recorded deployment backup, then restart only the dashboard backend. Existing event snapshots allow recovery of calendar content separately. Never restore the entire database over concurrent user changes without reconciling them.
